# ตามสถานการณ์

| สถานการณ์ | ใช้ทำอะไร |
|---|---|
| [เริ่มงาน/ตั้งค่า](/situations/start-setup) | ใช้เมื่อเพิ่งติดตั้ง PStack หรือกำลังจะเริ่มงานแรกในแชตใหม่ |
| [เข้าใจโค้ด](/situations/understand-code) | ใช้เมื่อต้องรู้ก่อนว่าโค้ดทำงานอย่างไรหรือทำไมถึงเป็นแบบนี้ และยังไม่ต้องการแก้อะไร |
| [ออกแบบ/วางแผน](/situations/design-plan) | ใช้เมื่อยังไม่ควรลงมือเขียน เช่นยังเลือก design ไม่ได้ หรือต้องวางแผนหลาย PR |
| [สร้างฟีเจอร์](/situations/build-feature) | ใช้เมื่อต้องเพิ่มหรือเปลี่ยน behavior ใหม่ |
| [เจอ bug](/situations/found-bug) | ใช้เมื่อมี defect ที่รายงานมาและต้องการ repro, หา root cause และ fix ด้วยหลักฐาน |
| [Review](/situations/review) | ใช้เมื่อ diff หรือ branch ใกล้เสร็จและอยากให้มีคนลองพังก่อนส่งต่อ |
| [Verify/เทส](/situations/verify-test) | ใช้เมื่อต้องพิสูจน์ว่างานใช้ได้จริงกับของจริง ไม่ใช่แค่ build ผ่าน |
| [Refactor/เก็บกวาด](/situations/refactor-cleanup) | ใช้เมื่อเปลี่ยนโครงสร้างหรือเก็บกวาดโดยไม่เปลี่ยน behavior |
| [Performance](/situations/performance) | ใช้เมื่อมีความช้าหรือตัวเลขที่ต้องวัด แก้ และเชื่อถือได้ |
| [เขียนเอกสาร/สื่อสาร](/situations/docs-communication) | ใช้เมื่อต้องเขียนหรือเล่าให้คนอ่านเข้าใจ เช่น docs, PR description หรือ reply ของ agent |
| [PR & Ship](/situations/pr-ship) | ใช้เมื่อโค้ดเสร็จและต้องเปิด PR ดูให้เขียว และ land |
| [ปล่อยรันเอง/ข้ามคืน](/situations/autonomous-overnight) | ใช้เมื่อจะเดินไปไหนแล้วให้ agent ทำต่อเองจนเสร็จ และกลับมาตรวจทีหลัง |
| [ปรับแต่ง PStack](/situations/customize-pstack) | ใช้เมื่ออยากให้ PStack เข้ากับวิธีทำงานของตัวเองหรือทีม |
| [ปัญหาที่เจอบ่อย](/situations/troubleshooting) | ตารางนี้ใช้เมื่อ run ไปผิดทาง แต่ละแถวบอกอาการ วิธีแก้ และตัวอย่าง |
