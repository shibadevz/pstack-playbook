# สร้างฟีเจอร์

ใช้เมื่อต้องเพิ่มหรือเปลี่ยน behavior ใหม่ หน้านี้อ่านได้โดยไม่ต้องใช้ database

## เริ่มจากสิ่งเหล่านี้ (เรียงตามลำดับ)

1. **Playbook: Feature** — ค่าเริ่มต้น: ใช้ how กับ subsystem, ออกแบบ, delegate โค้ด และตรวจบน surface ที่ตรงกัน. วิธีเรียก: พิมพ์ `/pstack:poteto-mode add <behavior>. <current output> stays byte-identical. verify both.`
2. **/pstack:architect** — ถ้า change ข้าม function boundary ให้ร่าง type และ module ก่อนเขียนโค้ด. วิธีเรียก: พิมพ์ `/pstack:architect`
3. **/pstack:arena** — ถ้า implementation มีหลายรูปแบบที่ใช้ได้ ให้หลาย candidate ทำแล้วเลือก base. วิธีเรียก: พิมพ์ `/pstack:arena`
4. **/pstack:principle-model-the-domain** — เมื่อ logic มี state หรือเงื่อนไขกระจัดกระจาย ให้ใส่ domain ลงโครงสร้างก่อนเขียน. วิธีเรียก: สั่งด้วยชื่อใน poteto-mode เช่น "apply model the domain" หรือพิมพ์ `/pstack:principle-model-the-domain`
5. **/pstack:typescript-best-practices** — ถ้างานอยู่ในไฟล์ `.ts` หรือ `.tsx`. วิธีเรียก: พิมพ์ `/pstack:typescript-best-practices`

## ตัวอย่าง prompt

```text
/pstack:poteto-mode add a --json flag to the export command. text output stays byte-identical. verify both.
```

เขียน prompt โดยบอก goal และ done check ที่ตรวจได้ ไม่ต้องไล่ชื่อ skill เอง ให้ `/pstack:poteto-mode` เลือกขั้นตอน
