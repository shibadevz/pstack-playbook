# ออกแบบ/วางแผน

ใช้เมื่อยังไม่ควรลงมือเขียน เช่นยังเลือก design ไม่ได้ หรือต้องวางแผนหลาย PR หน้านี้อ่านได้โดยไม่ต้องใช้ database

## เลือกใช้ตามสถานการณ์

ไม่ต้องใช้ครบทุกตัว เลือกตัวที่ตรงกับงานตอนนั้น ถ้าไม่แน่ใจให้เริ่มจากตัวแรก

- **Playbook: Prototype** — ทำต้นแบบทิ้งขว้างหลายแบบหลัง switcher แล้วเลือกจากสิ่งที่รันได้. วิธีเรียก: พิมพ์ `/pstack:poteto-mode prototype a few options for <feature>.`
- **/pstack:architect** — ร่าง type และ module boundary ก่อน พิมพ์ "with checkpoint" ถ้าอยากตรวจก่อนเขียนโค้ด. วิธีเรียก: พิมพ์ `/pstack:architect`
- **/pstack:arena** — ขอความเห็นที่สองเรื่อง design จากหลาย candidate. วิธีเรียก: พิมพ์ `/pstack:arena`
- **Playbook: Multi-phase or multi-PR plan** — เมื่อ design นิ่งแล้ว ให้เขียนแผนเป็น PR เล็กที่ตรวจได้ แผนคือ deliverable และไม่ implement. วิธีเรียก: พิมพ์ `/pstack:poteto-mode turn this design into a plan.`
- **/pstack:figure-it-out** — เมื่อไม่มี playbook ไหนพอดี เช่น migration ใหญ่ข้ามหลายจุด. วิธีเรียก: พิมพ์ `/pstack:figure-it-out`

## ตัวอย่าง prompt

```text
/pstack:poteto-mode ทำ prototype layout ของหน้า settings สองสามแบบ ใส่ไว้หลัง switcher แล้วส่ง screenshot ของแต่ละแบบมาให้
```

เขียน prompt โดยบอก goal และ done check ที่ตรวจได้ ไม่ต้องไล่ชื่อ skill เอง ให้ `/pstack:poteto-mode` เลือกขั้นตอน
